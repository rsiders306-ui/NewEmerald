# v0.1.0 startup failure analysis

## Result

The white screen was caused by a malformed expanded sound archive generated by
`nitrosfx`. It was a game-build defect, not a melonDS compatibility problem.

The SDAT `FILE` block in the failed ROM starts at `0x1D148`. Its 12-byte header
ends at `0x1D154`, and the writer pads the first payload to the next 32-byte
boundary at `0x1D160`. The old FAT calculation recorded `0x1D154`, so every one
of the 2,135 payload offsets pointed 12 bytes before the real data. The retail
archive happened to end its header on an aligned address, which hid the latent
bug until the archive grew.

melonDS reported `ARM9: data abort (020C64CC)`. Accounting for the ARM pipeline,
the faulting instruction is at `0x020C64C4` in `SND_AssignWaveArc`, where the
game dereferenced a wave-archive link from the malformed `BANK_BASIC` data.

The writer now starts FAT payload offsets at:

```c
fileOffset + PADDINGSIZE(fileOffset, 0x20)
```

The modified ARM9 also made the retail secure-area CRC stale. The packer now
applies the raw secure-area CRC delta during every build and then regenerates
the ordinary header CRC. For this build the secure-area CRC is `0xE8CE` and the
header CRC is `0x65AD`.

## Isolation and runtime tests

| ROM case | melonDS 1.1 result |
| --- | --- |
| Clean US Rev 1 | Boots |
| Failed target `9c54fe…` | White screen; ARM9 data abort |
| Failed target with only header CRCs corrected | Same ARM9 data abort |
| Failed target with retail SDAT substituted | Boots |
| Custom SDAT with all FAT offsets corrected | Boots |
| Final source build `e589b2…` | Reaches the Platinum title animation |

The final source build also reaches the title animation in DeSmuME 0.9.13.
The screenshots and melonDS log are stored in `docs/beacondex/evidence` and
their checksums are recorded in `data/beacondex/emulator_boot_report.json`.

`tools/beacondex/boot_integrity_audit.py` is now part of consolidated release
validation. It verifies the secure-area and header CRCs, locates the embedded
SDAT through NitroFS, checks all FAT offsets against the actual aligned payload
cursor, validates every sound-file magic, and confirms that the embedded SDAT
matches the generated build artifact. It rejects the failed target and passes
the repaired release.
